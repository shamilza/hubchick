**Версия документа:** 1.0  
**Дата:** 30 декабря 2025  
**Тип проекта:** SaaS CRM для самозанятых и микро-бизнеса (Mobile-first)  
**Статус:** Draft (MVP)

---

## 1. Общие сведения

### 1.1. Назначение системы
**Hubchick** — это облегченная CRM-система и сервис онлайн-записи, разработанный специально для самозанятых специалистов (beauty-мастера, репетиторы, консультанты, мастера на час).

**Ключевая ценность:** Избавление от рутины согласования времени, автоматизация напоминаний и упрощенный финансовый учет в "одном окне".

### 1.2. Целевая аудитория
*   **Мастер (Vendor):** Работает один, использует смартфон как основной инструмент, не разбирается в сложных настройках.
*   **Клиент (Customer):** Хочет быстро записаться на услугу без звонков и переписок.

---

## 2. Бизнес-логика и Роли

### 2.1. Роль: Мастер (Admin своего профиля)
Пользователь, который прошел регистрацию и верификацию.
*   **Функции:** Управление графиком, настройка услуг, просмотр базы клиентов, учет финансов.
*   **Ограничение:** Один аккаунт = один специалист (в MVP нет поддержки салонов с множеством сотрудников).

### 2.2. Роль: Клиент (Guest / User)
Пользователь, перешедший по публичной ссылке.
*   **Функции:** Просмотр слотов, бронирование, отмена записи.
*   **Авторизация:** Упрощенная (по номеру телефона или без авторизации с подтверждением по SMS в будущем).

## 3. Функциональные требования (MVP)

### 3.1. Модуль Onboarding и Профиль (Мастер)
**User Story:** Как Мастер, я хочу зарегистрироваться за 2 минуты, чтобы сразу начать работу.

*   **Регистрация:** Email/Телефон + Пароль (или Social Login: Google/Yandex).
*   **Мастер-визард (Настройка профиля):**
    1.  Имя / Название (напр. "Маникюр от Анны").
    2.  Специализация (выбор из списка).
    3.  Установка уникального `slug` (ссылки): `hubchick.com/anna_nails`.
*   **Настройка услуг:**
    *   Название.
    *   Стоимость (фиксированная или "от").
    *   Длительность (шаг 15 мин).

### 3.2. Модуль "Календарь и График"
**User Story:** Как Мастер, я хочу настроить свое рабочее время, чтобы клиенты не записывались ночью.

*   **Настройка расписания:**
    *   Рабочие дни (Пн-Пт / 2 через 2).
    *   Рабочие часы (напр. 10:00 - 20:00).
    *   Технические перерывы (обед).
*   **Управление записями (CRUD):**
    *   Создать запись вручную (имя, телефон, услуга, время).
    *   Перенести запись (Drag & Drop).
    *   Отменить запись (с уведомлением клиента).
*   **Блокировка слотов:** Возможность закрыть день или час как "Личное время".

### 3.3. Модуль "Публичная страница записи" (Booking Engine)
**User Story:** Как Клиент, я хочу видеть только свободное время и записаться в 3 клика.

*   **Интерфейс:** Mobile-first адаптив.
*   **Флоу записи:**
    1.  Выбор услуги (можно выбрать несколько, время суммируется).
    2.  Выбор даты (календарь).
    3.  Выбор времени (умный фильтр: показываем только свободные интервалы, учитывая длительность услуг).
    4.  Ввод данных (Имя, Телефон).
    5.  Экран "Спасибо" + SMS/Push уведомление.

### 3.4. Модуль "Клиентская База" (Mini-CRM)
**User Story:** Как Мастер, я хочу помнить историю посещений клиента.

*   **Список клиентов:** Поиск по имени/телефону.
*   **Карточка клиента:**
    *   Контакты (с кнопками "Позвонить", "Написать в WhatsApp").
    *   История визитов (Всего визитов, Последний визит).
    *   **LTV (Lifetime Value):** Сумма всех денег, оставленных клиентом.
    *   Поле "Заметки" (приватное для мастера).
*   **Черный список:** Запрет на онлайн-запись для конкретного номера.

### 3.5. Модуль "Финансы" (Упрощенный)
**User Story:** Как Мастер, я хочу видеть, сколько денег заработал сегодня.

*   **Дашборд:**
    *   Доход за День / Неделю / Месяц (авторасчет из выполненных записей).
    *   Возможность добавить "Прочий доход" или "Расход".
*   **Отчеты:** История операций (дата, описание, сумма, тип).

## 4. Технические требования

### 4.1. Стек технологий (Рекомендация)
*   **Frontend:** React (SPA) + PWA (Service Workers для работы офлайн). UI Kit: Mantine или Ant Design Mobile.
*   **Backend:** Python (FastAPI) — асинхронность важна для быстрой обработки слотов календаря.
*   **Database:** PostgreSQL (реляционные данные).
*   **Cache:** Redis (для блокировки слотов в момент выбора, чтобы избежать дабл-букинга).
*   **Deployment:** Docker контейнеры на VPS (Selectel / Yandex.Cloud / DigitalOcean).

### 4.2. Архитектура
```
┌─────────────────┐
│   React (PWA)   │ (Клиент браузер + Mobile App-like)
└────────┬────────┘
         │ HTTPS / REST API
         ▼
┌─────────────────────────┐
│  FastAPI Backend        │
│  (Async, Routing)       │
└────────┬────────────────┘
         │
         ▼
┌──────────────────────┐  ┌──────────────┐
│  PostgreSQL (DB)     │  │  Redis       │
│  (Сущности, Записи)  │  │  (Cache)     │
└──────────────────────┘  └──────────────┘
```

### 4.3. Безопасность и Данные
*   **Шифрование:** HTTPS (TLS 1.3).
*   **Auth:** JWT (Access 15 мин + Refresh 7 дней).
*   **Хранение паролей:** bcrypt / Argon2 (cost factor 12+).
*   **CORS:** Whitelist только для фронтенда.
*   **Rate Limiting:** 100 запросов/минуту на IP.
*   **SQL Injection защита:** Используем ORM (SQLAlchemy / Django ORM), параметризованные запросы.

### 4.4. Производительность
*   **API Response Time:** < 300 мс (p95).
*   **Загрузка публичной страницы:** < 2 сек.
*   **Максимальная нагрузка (MVP):** 100 одновременных пользователей.

## 6. API Structure (REST endpoints)

### 6.1. Authentication
```
POST   /api/v1/auth/register

POST   /api/v1/auth/logout
POST   /api/v1/auth/forgot-password
POST   /api/v1/auth/reset-password
```

### 6.2. Master Profile
```
GET    /api/v1/master/profile
PATCH  /api/v1/master/profile
GET    /api/v1/master/schedule
PATCH  /api/v1/master/schedule
```

### 6.3. Services
```
POST   /api/v1/services
GET    /api/v1/services
PATCH  /api/v1/services/{id}
DELETE /api/v1/services/{id}
```

### 6.4. Bookings (Master)
```
POST   /api/v1/bookings (создать вручную)
GET    /api/v1/bookings (список записей на месяц)
PATCH  /api/v1/bookings/{id} (перенести / отменить)
DELETE /api/v1/bookings/{id}
```

### 6.5. Public Booking (Клиент, без auth)
```
GET    /api/v1/public/{slug}/info (данные мастера, услуги)
GET    /api/v1/public/{slug}/slots?date=2025-12-30 (свободные слоты)
POST   /api/v1/public/{slug}/book (создать запись)
```

### 6.6. Customers (Master)
```
GET    /api/v1/customers
GET    /api/v1/customers/{phone}
PATCH  /api/v1/customers/{phone}
```

### 6.7. Finance
```
GET    /api/v1/finance/dashboard
GET    /api/v1/finance/history
POST   /api/v1/finance/add-expense
```

## 8. Этапы разработки (Roadmap)

### Phase 1: Core Backend & Auth (Неделя 1-2)
*   Проектирование БД (DDL скрипты).
*   Реализация Auth (регистрация, логин, JWT).
*   CRUD endpoints для Services, Schedule.
*   Unit-тесты для основных функций.

### Phase 2: Booking Engine (Неделя 3-4)
*   Алгоритм расчета свободных слотов (самая сложная часть).
*   API слотов: `GET /public/{slug}/slots`.
*   Логика бронирования: создание записи, блокировка Redis.
*   Обработка дабл-букинга (конкурентные запросы).

### Phase 3: Frontend & UI (Неделя 5-6)
*   React приложение (PWA).
*   Публичная страница записи (3 клика).
*   Интерфейс мастера: календарь, услуги, список клиентов.
*   Mobile-first адаптив.

### Phase 4: Notifications & Integrations (Неделя 7)
*   Подключение SMS шлюза (GreenAPI / SMS.ru / Twilio).
*   Email-уведомления (Sendgrid / Mailgun).
*   Автоотправка напоминаний за 1 час / 1 день до записи.

### Phase 5: Testing & Release (Неделя 8)
*   Load testing (нагрузочное тестирование).
*   Security audit (проверка на OWASP Top-10).
*   Публикация документов (Оферта, Политика ПД).
*   Деплой на продакшн.

**Итого до MVP:** ~2 месяца для команды из 2 разработчиков (1 Backend + 1 Frontend).

### 9.1. Монетизация

## 11. FAQ для разработчиков

**Q: Нужна ли мне база клиентов для Мастера?**  
A: Да, но она автоматически заполняется из бронирований. При первой записи создается запись в `customers`.

**Q: Как обрабатывать no-show (клиент не пришел)?**  
A: Мастер может отметить статус записи как "no_show". На этапе v2 можно добавить штраф (требование предоплаты).

**Q: Почему не берем платежи на MVP?**  
A: Потому что это добавляет сложность (эквайринг, 54-ФЗ, PCI-DSS). На MVP фокусируемся на ядре: запись + уведомления.

**Q: Как работает расчет слотов?**  
A: Берем рабочее время из `schedule`, вычитаем существующие `bookings`, получаем свободные интервалы.
